852: 8.4.3 Box/Kit Fulfillment & ATP Check
853: Every outbound order triggers an ATP (Available-to-Promise) check. The ATP engine:
854: Checks AVAILABLE inventory of each order line at the preferred fulfillment location (or nearest available location).
855: For BOM/kit products: expands the BOM into components and checks each component's availability.
856: If all components are co-located: ATP date = today + transit time (from Transit Time Master) to customer.
857: If components are split across locations: the engine identifies the missing components, checks alternate locations, and calculates: transit time to consolidate at fulfillment location + assembly time (from Assembly Time Master) + transit time to customer.
858: The ATP result is displayed to the Supply Planner showing: fulfilling location, expected ship date, expected delivery date.
859: The Supply Planner can adjust order quantity or date. Each adjustment triggers a recalculation. If the requested date is not achievable, a red warning message is displayed: 'ATP infeasible — earliest possible delivery is [date].' The Supply Planner can acknowledge the warning and proceed with their own date (override decision recorded).
860: 
861: Note: Specific serial number allocation happens at the Allocated status, not at order creation. ATP confirms count feasibility only.
862: R2: When components must be sourced from multiple locations, the system will in Release 2 automatically generate a Work Order sent to the relevant Warehouse User, instructing them to prepare the assembly.

872: 8.4.5 Replacement Orders
873: Replacement Orders are auto-drafted by the system when a Return Order reaches Initiated status (see 8.5.1). The auto-drafted Replacement Order is pre-populated with:
874: Same customer as the Return Order
875: Same product as the returned terminal (or the best available alternative product if the same product has zero AVAILABLE inventory)
876: Same source warehouse as the originating outbound order
